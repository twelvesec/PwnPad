# Challenge 14: "Ladybirds" 

A compact safe is protected by a stubborn firmware check — pry it open with the debug port:
The device exposes SWD pads. The safe unlocks when a specific memory location  is set — you must patch memory or the flash image to bypass the check.
This challenge expects use of an ST-Link together with gdb-multiarch (or an equivalent GDB server) to halt the CPU, inspect memory/flash, and apply a non-destructive patch to reveal the safe contents.

Your mission is clear:

1. Expose and identify the SWD pads on the board. Verify the target voltage domain (do not assume 3.3V) and connect your ST-Link (observe correct ground and VTarget).
2. Bring up a GDB server for the ST-Link (for example st-util or openocd), then connect with gdb-multiarch
3. Halt the core and capture state (monitor reset halt / interrupt), then locate the authentication routine.
4. Inspect RAM and flash to find the check
5. Perform the patch and unlock the safe
